# 公開前の Secret Scan と依存監査

確認日: 2026-09-14

## Secret Scan

```sh
npm run secret-scan
node scripts/secret-scan.mjs --self-test
```

`scripts/secret-scan.mjs` は、このアプリの Git 管理済みファイルと未追跡の公開候補ファイルを検査します。独立した Git repository の作成前にも、アプリのソースツリーを検査できます。Git 管理外に置かれた `.env` などの機密ファイル名も追加確認します。

既知の GitHub/API/Slack/AWS/Google 認証情報、秘密鍵、認証情報入りURL、プレースホルダー以外の credential assignment、機密ファイル名を検出します。候補があれば終了コード `1` を返します。出力はファイル名・行番号・判定ルールだけで、値は表示しません。検査パターンと自己検証用の疑似値はコード中で分割して組み立て、スクリプト自身に実形式の秘密情報を記載しません。

除外対象は `node_modules`、`.next`、`.vercel`、`.git`、`out`、一時ファイル、ログ、テスト出力、PDF/PNG/XLSX/フォントなどのバイナリアセットです。SVGやアプリに配信するJavaScriptはテキストとして確認します。スクリーンショット・架空のサンプルPDFは、別途人が内容を確認します。

実行結果: **PASS — 既知のsecretパターン・機密ファイル名の候補なし**。検知の自己検証もPASS。README・スクリーンショット・ポートフォリオ用プロンプトを加えた最終公開対象についても再実行し、候補0件を確認しました。

この検査は公開対象の現行ファイルの確認です。Gitの過去履歴全体、バイナリ内の機密情報、未知の形式、外部サービス上の状態を網羅する保証はありません。アプリはAPIキー・アカウント・サーバー環境変数を必要としません。

## 本番依存パッケージの監査

```sh
npm audit --omit=dev
```

初回監査では、ExcelJS 4.4.0 → uuid 8.3.2 の依存経路に `moderate` 2件を検出しました。2件は同じ問題の直接パッケージ・依存元の集計です。`high` / `critical` は0件でした。ExcelJS配下のuuidを11.1.1に固定して再インストールした後、独立して再監査し、**全深刻度で0件**を確認しました。

対象は [GHSA-w5hq-g745-h8pq / CVE-2026-41907](https://github.com/advisories/GHSA-w5hq-g745-h8pq) です。uuidのv3/v5/v6関数に外部バッファを渡す場合の境界検証に関する問題で、uuid 11.1.1で修正されています。実際のExcelJSソースが呼び出すのはv4()だけです。CommonJSとブラウザの両方のexportsを提供するuuid 11.1.1に、package.jsonの`overrides.exceljs.uuid`で依存を固定しました。npmが提示する旧ExcelJSへの大幅ダウングレードは採用していません。依存更新時には監査・XLSX出力検証・本番ビルドを再実施してください。

## ファイル入出力のソースレビュー

- PDFは`File.arrayBuffer()`からPDF.jsへ渡し、抽出・編集・出力はブラウザ内で処理します。ユーザーPDF・セル値を送信するAPI呼び出しはありません。
- 通信するのは、アプリ自身の配信ファイル、同一オリジンのPDF.jsアセット、選択された架空サンプルPDFです。
- CSVはUTF-8 BOM付き、引用符・改行・カンマをエスケープし、式として解釈される先頭文字には単一引用符を補います。
- XLSXのセル値は文字列として書き込み、PDFの値から式・マクロ・外部リンクを生成しません。
- 出力はローカルBlob URLを作成し、ファイル名に使えない区切り文字・制御文字を置換します。Blob URLは出力開始後に破棄します。
- 画面のセル値・ファイル名・エラー表示はReactのテキスト/入力値として描画します。抽出結果をHTMLとして挿入しません。
- 25MB・100ページの入力制限があります。PDF内容の複雑さによって処理時間やメモリ使用量は変わります。
